# Карточка доступа к серверу

> **Агент, это твой единственный источник правды о том, как попадать на сервер владельца.**
> Читай этот файл перед подключением. Обновляй его сразу после любого изменения входа
> (новый ключ, новый пользователь, выключенный пароль, другой порт). Если подключиться
> не удалось - сначала перечитай карточку, а не перебирай варианты.
>
> Секреты сюда не пишем: только путь к ключу, а не сам ключ; никаких паролей.

## Как я подключаюсь

| Поле | Значение |
|---|---|
| IP сервера | `{ЗАПОЛНИТЬ}` |
| Провайдер | SmartApe (или свой), локация Чехия |
| Порт SSH | 22 (менять не будем) |
| Пользователь, под которым я хожу | `{ЗАПОЛНИТЬ: root или свой}` |
| Способ входа | ключ / пароль |
| Путь к приватному ключу на этой машине | `{ЗАПОЛНИТЬ, например ~/.ssh/id_ed25519}` |
| Рабочая команда подключения | `ssh -i ~/.ssh/id_ed25519 ПОЛЬЗОВАТЕЛЬ@IP` |
| Как получаю root | вхожу как root / `sudo` без пароля / `sudo` с паролем |
| Дата последней проверки, что это работает | `{ДАТА}` |

## Аварийный вход (это важнее, чем кажется)

| Поле | Значение |
|---|---|
| Аварийная (VNC) консоль в кабинете провайдера | есть / нет, прямая ссылка: `{ЗАПОЛНИТЬ}` |
| Логин в личный кабинет провайдера | `{ЗАПОЛНИТЬ, пароль - в менеджере паролей}` |
| Последний снимок (snapshot) сервера | `{ДАТА или "нет"}` |

Если аварийной консоли нет или снимок не сделан - **никакие настройки входа не трогаем**.
Сначала находим консоль и делаем снимок, потом всё остальное.

## Что менялось в доступе

Веди журнал: одна строка на изменение, новые сверху. Так видно, после чего именно всё сломалось.

- `{ГГГГ-ММ-ДД}` - что изменил, как проверил, что вход жив.

## Правила, которые не нарушаются

1. **Второе окно.** Любая правка SSH, файрвола или пользователей делается при открытой второй сессии. Первую не закрываем, пока во второй не убедились, что вход работает.
2. **Не выключаем вход root, пока не создан второй пользователь с sudo и не проверен реальный вход по ключу под ним.** Не «должно работать», а «зашёл и вижу приглашение».
3. **Не меняем порт SSH.** Выгоды почти нет, а способов запереться - много.
4. **Не включаем файрвол, не разрешив предварительно SSH.** Порядок: сначала правило `allow OpenSSH`, потом `enable`.
5. **Не пускаем в перебор.** Не пустило два раза - СТОП. Перечитал карточку, посмотрел журнал изменений, пошёл в аварийную консоль. Дальнейшие попытки только добавят бан в fail2ban и сделают хуже.
6. **После каждой правки - обновить эту карточку.** Это и есть страховка от ситуации, когда сервер защищён, а зайти на него не может никто, включая меня.

## Если не пускает

1. `Permission denied (publickey)` - ключ не тот или не тот пользователь. Смотри карточку: под кем и с каким ключом ходили в прошлый раз.
2. `Connection closed by remote host` после нескольких попыток - скорее всего fail2ban забанил твой адрес. Ждать (обычно 10-60 минут) или зайти через аварийную консоль и разбанить. **Не долбиться.**
3. `Connection timed out` - файрвол или сервер выключен. Проверь состояние сервера в кабинете провайдера.
4. Ничего из этого не помогло - аварийная консоль провайдера, вход с локальной клавиатуры, откат к снимку.
