# Hermes на сервере: помощник, который работает без ноутбука

> **Предусловие:** сервер куплен заранее, в pre-work, и настроен по `ustanovka/vps-smartape.md` (или у другого провайдера из `ustanovka/vps.md` - шаги дальше те же). Есть IP-адрес, есть пользователь `agent`, вход по ключу работает (`ssh jarvis`), файрвол и fail2ban включены, вход по паролю отключён. Это спринт 1 второго дня - `uroki/den2-s1-server.md`.

Инструкция без развилок. Делай ровно по шагам, сверху вниз.

> [!tip] Руками не настраивай
> Все команды ниже выполняет агент. Ему нужен **IP-адрес** и ключ или пароль root из письма хостера - отдай их готовым промптом из `ustanovka/server-dostup.md`. Доступ отзываем на аудите второго дня.
> Не может подключиться — спроси прямо: «что тебе ещё дать из данных?».

---

Агент, ты ведешь участника по этой инструкции. Правила:
- Строго по одному шагу, жди подтверждения.
- Команды на сервере выполняй сам, проговаривая своими словами, что делаешь.
- Ключ модели и токен бота участник отдаёт тебе в чат, как пароль root (правила - `ustanovka/server-dostup.md`). Записываешь их сам: `hermes config set ИМЯ значение` кладёт секрет в `~/.hermes/.env`. Значения в ответах не повторяй, в файлы волта не пиши **никогда**.
- **Интерактивное не запускай.** Мастер `hermes setup`, `hermes setup gateway`, nano и чат `hermes` ждут ввода с клавиатуры, а у тебя нет окна, куда участник мог бы печатать. Всё настраивается командами шагов 3, 4 и 6, проверка ответа - `hermes -z "вопрос"`.
- Файлы `~/.hermes/.env` и `~/.hermes/config.yaml` целиком или кусками **не выводи** — там лежат ключи. Есть ли ключ, проверяй без значения: `grep -c '^ANTHROPIC_API_KEY=.' ~/.hermes/.env`.
- После каждого шага сверяйся с блоком «что участник должен увидеть». Не сошлось - не идем дальше.

## Что мы делаем и зачем

На ноутбуке помощник умеет отвечать. На сервере он начинает **работать сам**: утром собирает сводку, следит за источниками, выполняет задачи по расписанию, пишет в мессенджер. Ноутбук при этом закрыт и лежит в сумке.

Переселение - это шесть вещей: войти, поставить, дать мозги, дать память, поднять как службу, дать расписание.

## Если Hermes уже настроен на ноутбуке: это переезд, а не установка

После дня 1 у большинства Hermes уже живет локально: бот, волт, голос. Тогда иди по шагам ниже как написано - на чистой машине это быстрее, чем было на ноутбуке (ни SmartScreen, ни корпоративных политик), - но бота **переключаем**, и порядок важен.

> [!warning] Токен бота живет только в одном Hermes
> Если гейтвей запущен и на ноутбуке, и на сервере с одним токеном - они отбирают сообщения друг у друга. Выглядит как мистика: бот отвечает через раз, вперемешку старой и новой памятью. Это главная засада переезда.

Порядок переключения:
1. Пройди шаги 1-5 и проверь помощника в терминале - Telegram на этом этапе НЕ подключай.
2. Перенеси настройки с ноутбука: агент читает локальные `~/.hermes/config.yaml` и `~/.hermes/.env` и повторяет на сервере нужное - модель, `stt.provider`, `stt.language ru`, ключи GROQ_API_KEY и EXA_API_KEY. Значения ключей агент переносит сам командой `hermes config set ИМЯ значение` (шаг 4), в ответах их не повторяет.
   **Про голосовые отдельно:** если `stt.provider` нигде не задан, сервер и так их распознает - Hermes берет локальный faster-whisper с моделью `base`, без ключей и без интернета. На 2 ядрах это 5-15 секунд на сообщение и слабое качество на русском, поэтому лучше перенести Groq. Разбор вариантов и как поднять локальную модель до `small` - в `ustanovka/hermes.md`, блок про распознавание голосовух.
3. На ноутбуке останови гейтвей и убери из автозапуска: `hermes gateway stop`; если ставил фоновым сервисом - сними службу. Иначе после перезагрузки ноутбук проснется и снова начнет воровать сообщения у сервера.
4. Только теперь шаг 6: подключай Telegram на сервере тем же токеном.
5. Проверка: крышка ноутбука закрыта, пишешь боту с телефона - отвечает и помнит вчерашнее. Переезд состоялся.

Hermes на ноутбуке можно оставить для работы за столом - но без гейтвея: в Telegram теперь отвечает сервер.

## Мини-интервью

1. IP-адрес сервера под рукой, `ssh jarvis` пускает без пароля?
2. Доступ к моделям есть? Берем тот же, что на ноутбуке: его выдает бот тренинга, подписка на нейросети включена в стоимость (`ustanovka/klyuch-trening.md`). Есть своя подписка - можно жить на ней (`ustanovka/minimax.md`, `ustanovka/kimi.md`).
3. Волт уже лежит в **приватном** репозитории на GitHub? Если нет - сначала `ustanovka/volt-cherez-github.md`, без этого шага 5 не сделать.

## Шаг 1. Войти на сервер под пользователем agent

Открой терминал (Mac - «Терминал», Windows - PowerShell) и выполни:

```
ssh jarvis
```

Это короткий алиас, который завели в `ustanovka/vps-smartape.md`, шаг 7.3. Алиаса нет — полная форма:

```
ssh -i ~/.ssh/jarvis_vps agent@АДРЕС_СЕРВЕРА
```

Под `root` помощника **не ставим**: одна кривая команда от имени root ломает сервер целиком.

**Что участник должен увидеть:** приглашение вида `agent@vps-12345:~$`.

## Шаг 2. Поставить Hermes

Сначала — системные пакеты. Если сервер настраивали по `ustanovka/vps-smartape.md`, они уже стоят (шаг 7.1), команда просто ничего не сделает:

```
sudo apt-get install -y git libatomic1 ffmpeg ripgrep
```

Без `git` установщик останавливается на первой строке: `git is required` (в образе Ubuntu 26.04 у SmartApe его нет).

> [!warning] Без libatomic1 установщик уходит в бесконечный круг
> Node.js без этой библиотеки не стартует, а установщик считает, что Node не поставился, и качает его заново. Так по кругу, пока не надоест. В логе при этом всё выглядит благополучно: ошибка `libatomic.so.1: cannot open shared object file` проскакивает одной строкой между двумя сообщениями об успехе.

Официальный установщик. Идёт 10–20 минут, поэтому запускаем его так, чтобы он **не умер вместе с окном терминала**: любой обрыв связи в середине означает начинать заново.

```
nohup bash -c 'curl -fsSL https://hermes-agent.nousresearch.com/install.sh | bash -s -- --skip-setup' > ~/hermes-install.log 2>&1 &
```

Флаг `--skip-setup` нужен потому, что установка идёт в фоне, без окна: так установщик не ждёт ответов мастера и не ставит службу сам. Мастер (`hermes setup`) мы проходим на шаге 3, службу Telegram - на шаге 6. Других флагов не добавляй: с октября 2026 неизвестный флаг останавливает установку с ошибкой `unknown option`.

Следить за ходом:

```
tail -f ~/hermes-install.log
```

Выйти из слежения — `Ctrl+C`, установка при этом продолжается. Готово, когда лог перестаёт расти и в конце стоит сообщение об успешной установке, обычно с подсказкой запустить `hermes setup`. Подробный лог самого установщика - `~/.hermes/logs/install.log`.

Установщик сам притащит всё остальное: Python, Node.js, зависимости.

> [!info] Ругань в логе, на которую не надо реагировать
> Строка `error: The lockfile at 'uv.lock' needs to be updated, but '--locked' was provided` выглядит как падение, но установщик сам переходит на резервный путь через PyPI и ставится нормально. Смотри на итог, а не на эту строку.

Перезагрузи окружение и проверь, что программа на месте:

```
source ~/.bashrc
hermes --version
hermes doctor
```

**Что участник должен увидеть:** `hermes --version` печатает номер версии, `hermes doctor` не показывает красного.

## Шаг 3. Визард настройки

> [!important] Агент из OpenCode визард не запускает
> Визард - это экраны со стрелками и пробелом, ему нужно окно для ввода, а у агента его нет: запуск зависнет или выйдет с подсказкой «no TTY». Агент, пропусти визард. Модель и ключ задашь на шаге 4, Telegram - на шаге 6, а из экранов визарда нужен только голос:
>
> ```
> hermes config set tts.provider edge
> ```
>
> Остальное в свежей установке уже стоит как надо: терминал Local, навыки, память и задачи по расписанию включены. Таблица ниже - для того, кто проходит визард сам в своём терминале.

```
hermes setup
```

Экраны те же, что были на ноутбуке в `ustanovka/hermes.md`. Правило клавиш повтори участнику вслух, оно тут снова спасает:

- **Кружки (● / ○)** - выбор одного пункта: стрелками довел курсор до строки, нажал Enter.
- **Квадратные скобки ([ ])** - выбор нескольких: **пробел ставит галочку**, Enter подтверждает список. Enter без пробела = ничего не выбрано.

Что выбираем на сервере:

| Экран | Ответ |
|---|---|
| How would you like to set up Hermes | **Full setup** |
| Select provider | **MiniMax в списке нет - и не надо его там искать.** Бери любой (например Anthropic) и проходи дальше: доступ мы пропишем файлом на шаге 4, он перекроет выбор визарда |
| Select default model | что предложит - неважно, модель зададим на шаге 4 командой |
| Select terminal backend | **Local** - команды выполняются прямо на этом сервере |
| Messaging Platforms | Enter, ничего не отмечая. Телеграм подключим отдельной командой на шаге 6 |
| Tools | галочки на **Skills, Memory, Cron**. **Computer Use снять** - на сервере нет экрана |
| Браузер | **Local Browser** (recommended, free) |
| Картинки | пропусти (`n` / без выбора). Генерация картинок к работе помощника отношения не имеет, а на выданном доступе не заработает |
| Озвучка | **Microsoft Edge TTS** |
| Web Search | на вопрос про Nous Portal login отвечай `n` |

Проверка:

```
hermes
```

Спроси «привет, какая у тебя модель». Выйти из чата - `/exit`.

**Что участник должен увидеть:** помощник ответил и назвал модель.

> [!warning] Про расход на сервере
> Помощник на сервере работает сам, по расписанию, без тебя. Значит и лимиты тратит без тебя. Подписка на нейросети на время тренинга включена в стоимость, но она не бесконечная: пока не убедился, что все настроено, не назначай задачи чаще одного раза в сутки. После тренинга, на своем ключе, обязательно поставь лимит - настройки по умолчанию плюс частое расписание за месяц набивают счет в сотни долларов.

## Шаг 4. Доступ к моделям лежит в защищенном файле

Секреты Hermes держит в `~/.hermes/.env`, настройки - в `~/.hermes/config.yaml`.

Участник присылает агенту в чат ключ из кабинета MiniMax (`sk-cp…`, тот же, что выдал бот тренинга). Агент записывает его сам - `hermes config set` кладёт секрет в `.env`, nano не нужен:

```
hermes config set ANTHROPIC_BASE_URL https://api.minimax.io/anthropic
hermes config set ANTHROPIC_API_KEY ключ_из_бота
hermes config set model.provider anthropic
hermes config set model.base_url https://api.minimax.io/anthropic
hermes config set model MiniMax-M3
chmod 600 ~/.hermes/.env
```

Адрес задаётся дважды намеренно: свежие версии Hermes берут его из `model.base_url`, старые - из `ANTHROPIC_BASE_URL`. `model.provider` - именно `anthropic`, не `custom`: протокол у MiniMax Anthropic-совместимый.

> [!warning] Имя переменной менять нельзя
> В гайдах MiniMax встречается `ANTHROPIC_AUTH_TOKEN` - **у Hermes переменная называется иначе**, ровно как написано выше. Скопируешь гайд дословно - ключ не доедет и получишь «неверный ключ» при верном ключе.
> Полный разбор и вариант для OpenCode - `ustanovka/klyuch-trening.md`.

Проверка без чата:

```
hermes -z "привет, какая у тебя модель?"
```

Шлюз уже запущен (переезд, повторная настройка) - `hermes gateway restart`.

Участник настраивает сам в своём терминале - те же команды, или `nano ~/.hermes/.env` и две строки `ANTHROPIC_BASE_URL=…` и `ANTHROPIC_API_KEY=…`.

**Что участник должен увидеть:** помощник ответил и назвал модель, `hermes doctor` без красного.

## Шаг 5. Дать доступ к волту

Здесь помощник получает твою память. Волт едет на сервер через **приватный** репозиторий GitHub.

> [!info] Волт лежит на Яндекс.Диске, а не на GitHub - две дороги
> 1. **Рекомендуем: завести приватный репозиторий** по `ustanovka/volt-cherez-github.md`. Диск при этом остаётся для телефона и резервной копии. Что даёт: история каждой правки с откатом и без дублей «файл (1)», когда ноутбук и сервер правят базу одновременно.
> 2. **Подключить Диск к серверу по WebDAV** - `ustanovka/yandex-disk.md`, вариант Б. Пароль приложения Яндекса участник создаёт сам (начинает действовать через 2-3 часа после создания) и присылает агенту. Агент монтирует Диск через `davfs2` с `use_locks 0` и прописывает монтирование в `/etc/fstab` с опцией `_netdev`, иначе после перезагрузки сервера база пропадёт. Тогда ключ репозитория, `git clone` и cron ниже пропусти, а `terminal.cwd` укажи на папку базы внутри смонтированного Диска - полный путь, без `~`. Минусы: Яндекс режет частые запросы по WebDAV, при одновременных правках бывают дубли, истории правок как в репозитории нет.

Сделай серверу собственный ключ доступа к репозиторию:

```
ssh-keygen -t ed25519 -C "vps-hermes" -f ~/.ssh/id_ed25519 -N ""
cat ~/.ssh/id_ed25519.pub
```

Вторая команда напечатает строку, начинающуюся с `ssh-ed25519`. Скопируй ее целиком.

Дальше участник делает руками в браузере:

1. Открыть свой репозиторий волта на github.com.
2. **Settings** - в левом меню **Deploy keys** - кнопка **Add deploy key**.
3. Title: `vps`. Key: вставить скопированную строку.
4. Поставить галочку **Allow write access** - иначе сервер сможет только читать, а он должен и записывать свои заметки.
5. **Add key**.

Возвращаемся на сервер, забираем волт. Первая строка заранее отвечает «да» на вопрос о подлинности GitHub, иначе `git clone` остановится и будет ждать ввода, которого агент дать не может:

```
ssh-keyscan -t ed25519 github.com >> ~/.ssh/known_hosts
git clone git@github.com:ТВОЙ_ЛОГИН/ТВОЙ_РЕПОЗИТОРИЙ.git ~/volt
```

Скажи помощнику, что волт - его рабочая папка. Путь только полный, без `~`:

```
hermes config set terminal.cwd /home/agent/volt
```

Ключа `workspace` в Гермесе нет: с ним он молча работает из домашней папки и не видит `AGENTS.md` волта.

**Что участник должен увидеть:** `ls ~/volt` печатает папки волта, среди них `AGENTS.md`; `hermes config get terminal.cwd` печатает `/home/agent/volt`.

Синхронизация раз в десять минут, чтобы ноутбук и сервер не расходились:

```
(crontab -l 2>/dev/null; echo "*/10 * * * * cd ~/volt && git pull --rebase --autostash -q && git add -A && git diff --cached --quiet || (git commit -qm 'vps sync' && git push -q)") | crontab -
```

**Что участник должен увидеть:** `crontab -l` показывает эту строку.

> [!warning] Что в репозиторий не уезжает
> Ключи, пароли, `.env`, базы с персональными данными, тяжелые медиафайлы. За это отвечает `.gitignore` в волте. Проверь, что он на месте, до первой синхронизации.

## Шаг 6. Телеграм и автозапуск

Участник заводит бота в @BotFather (`/newbot`, имя, ник на `bot` - путь B в `ustanovka/tg-bot.md`) и присылает агенту две вещи: **токен бота** (вида `1234567890:AA…`) и **свой числовой Telegram-ID** (пришлёт @userinfobot). ID обязателен: пустой список разрешённых = бот открыт всем, и любой жжёт твой ключ.

Агент записывает и ставит службу сам, без мастера:

```
hermes config set TELEGRAM_BOT_TOKEN токен_бота
hermes config set TELEGRAM_ALLOWED_USERS ID_участника
hermes config set TELEGRAM_HOME_CHANNEL ID_участника
sudo loginctl enable-linger agent
hermes gateway install
systemctl --user status hermes-gateway --no-pager
```

Переменная - именно `TELEGRAM_ALLOWED_USERS`. Других имён (`HERMES_ALLOWED_USERS` и подобных) Hermes не читает: бот с такой строкой открыт всем. `TELEGRAM_HOME_CHANNEL` - личка участника, туда приходят утренние сводки. `hermes gateway install` ставит фоновую службу и запускает её, вопросов не задаёт, когда окна для ввода нет. `enable-linger` - чтобы служба пережила выход из ssh и перезагрузку.

Участник в своём терминале может вместо этого пройти мастер: `hermes setup gateway`, стрелкой до **Telegram**, **пробел** (галочка!), Enter, дальше по `ustanovka/tg-bot.md`; на вопрос про фоновый сервис - **Y**.

**Что участник должен увидеть:** в статусе зеленое `active (running)`.

Служба шлюза должна быть одна. Если поставить и пользовательскую (`systemctl --user`), и системную (`sudo hermes gateway install --system`), бот уходит в бесконечный перезапуск. После смены рабочей папки или обновления Гермеса - `hermes gateway restart`.

Настоящая проверка: закрой окно терминала совсем, возьми телефон и напиши боту.

**Что участник должен увидеть:** бот ответил при закрытом ноутбуке.

## Шаг 7. Личность

Помощник уже видит волт. Теперь пусть прочитает правила и профиль владельца. Агент из OpenCode проверяет разовым запросом, без чата:

```
hermes -z "Прочитай AGENTS.md и profile/me.md в рабочей папке и коротко перескажи, кто я и по каким правилам ты работаешь"
```

Участник может спросить то же самое у бота в Telegram: шаг 6 уже сделан.

Проверка, что бот в Telegram видит волт: напиши ему `/new`, затем `/context` - в списке должен быть `AGENTS.md`. Нет его - рабочая папка не задана, вернись к шагу 5 (`terminal.cwd`) и перезапусти шлюз.

Характер и тон агента живут в `~/.hermes/SOUL.md` - это его душа, один файл на агента. Правила работы с базой - в `AGENTS.md` волта. Быстрый способ настроить личность - команда `/initiate-setup` в Telegram: агент сам расспросит о тебе и допишет настройки.

**Что участник должен увидеть:** ответ фактами из волта, а не общими словами.

## Шаг 8. Первая задача по расписанию

Одна задача, дешевая, а не пять сразу. Участник пишет боту в Telegram:

> Каждое утро в 9:00 по моему местному времени присылай мне в телеграм короткую сводку: что я записал в волт за последние сутки и какие задачи открыты.

Проверь, что задача записалась:

```
hermes cron list
```

**Что участник должен увидеть:** задача в списке с временем следующего запуска. Настоящая проверка будет завтра утром - это домашнее задание.

## Шаг 9. Проверка перезагрузкой

Ради этого все и делалось. Перезагружаем сервер и убеждаемся, что помощник встал сам:

```

Подожди две минуты, потом с телефона напиши боту.

**Что участник должен увидеть:** бот отвечает, хотя на сервер после перезагрузки никто не заходил.

## Если что-то пошло не так

| Симптом | Что делать |
|---|---|
| `command not found: hermes` после установки | `source ~/.bashrc`, либо выйди и зайди по ssh заново |
| Установщик крутится по кругу: качает Node, снова качает Node | Нет `libatomic1`. Прерви, поставь `sudo apt-get install -y libatomic1` и запусти установщик заново. Проверить причину: `grep -i libatomic ~/hermes-install.log` |
| Установка оборвалась вместе с интернетом | Так и бывает, если запускать не через `nohup`. Запусти командой из шага 2 и следи через `tail -f ~/hermes-install.log` |
| Установщик падает на середине | `sudo apt update && sudo apt upgrade -y`, дождись снятия блокировки (`while fuser /var/lib/dpkg/lock-frontend >/dev/null 2>&1; do sleep 5; done`), затем запусти установщик снова |
| `Permission denied (publickey)` при `git clone` | Deploy key добавлен не в тот репозиторий либо скопирована не вся строка. Повтори `cat ~/.ssh/id_ed25519.pub` и вставь целиком |
| Волт клонировался, но помощник его не видит | `hermes config get workspace` - должно быть `/home/agent/volt` |
| `git push` из cron не проходит | В Deploy key не стоит галочка **Allow write access**. Поставь и подожди десять минут |
| `systemctl --user status` пишет, что службы нет | Служба не поставилась. `hermes gateway install`, потом снова `systemctl --user status hermes-gateway` |
| Бот отвечает чужим или молчит на тебя | Проверь, что список разрешённых записан именно в `TELEGRAM_ALLOWED_USERS`: `grep -c '^TELEGRAM_ALLOWED_USERS=.' ~/.hermes/.env` должен дать 1. После правки - `hermes gateway restart` |
| После перезагрузки бот молчит | Не выполнен `sudo loginctl enable-linger agent`. Выполни и перезагрузись еще раз |
| Помощник не отвечает, но служба живая | `hermes doctor`, дальше проверяй ключ и баланс на счету провайдера |
| Сжигает деньги | `hermes cron list`, сними задачи, поставь дешевую модель, поставь лимит на ключе. Разбираться будешь потом |

## Что делать, если сервера нет

Сервер - это pre-work: его покупают до тренинга (`ustanovka/vps-smartape.md`). Не успел - заказывай сейчас, это 15 минут, но группа ждать не будет: догоняешь параллельно.

Пока сервера нет, все то же самое работает на ноутбуке по `ustanovka/hermes.md`, кроме одного: задачи по расписанию выполняются, только пока ноутбук включен и не спит. На один день этого хватит, но автоматика без твоего участия начинается только на сервере.
